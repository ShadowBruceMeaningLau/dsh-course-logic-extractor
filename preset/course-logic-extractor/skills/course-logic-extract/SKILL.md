# 课程逻辑提取（course-logic-extract）

## 使命

给定一门课程的任意形态资料（目录、大纲、讲义、课件、字幕、习题、实验、项目说明、参考书目……），还原这门课的**设计逻辑**：

- **顺序**：课程先干什么、后干什么，为什么是这个顺序而不是别的顺序；
- **意图**：每个环节为什么存在、为什么放在这个位置、它服务于什么能力；
- **逻辑链**：把上述判断串成一条自洽、可解释、可验证的因果链。

最终交付物是**设计逻辑分析报告**，服务对象是「还没开始正式学习、想先看清全局」的人。

## 边界（什么不是本技能）

- 不是内容笔记/摘要：不逐章复述知识点，内容细节只在支撑设计判断时出现。
- 不是大纲提取：不产出设问式学习清单；本技能回答「为什么这样组织」，不回答「每章要学什么」。
- 不是课程评价：可以指出设计的得失，但服务于解释设计逻辑，不写成评测报告。

## 用户使用说明（先答再干）

用户询问「怎么用 / 如何使用 / 使用说明 / 这个 agent 怎么用 / 你能做什么」等（任何类似措辞，包括创建会话、任务写法、交付物、常见问题的提问）时：**先 read 本技能目录的 `USAGE.md`，以其内容为准完整呈现**（可直接转述全文，或按用户的具体问题聚焦相应小节），不要凭记忆自行发挥、不要省略「交付物 / 常见问题」中的关键条目。用户明确表示已了解、并给出课程资料后，再进入正常提取流程。

## 输入形态与处理

| 形态 | 处理 |
| --- | --- |
| 本地目录（最常见） | glob/pwsh 盘点 → read 逐文件读取 |
| 粘贴的文本 | 直接作为资料处理，仍先划骨架再分析 |
| HTML 课件页（导出的网页课程） | 直接读源码提取标题与正文（标题=骨架，正文=内容）；页面文字已包含在文件里，无需 OCR，图片多为配图 |
| 网页课程/URL | 用 web 工具抓取目录与章节页（fetch 已开启）；抓不到则请用户提供文本 |
| 图片/扫描件/无文本层 PDF | 用自带脚本 `scripts/dsocr2md.mjs`（**GLM-OCR，智谱**）批量转 Markdown；单张「看图理解」用 `image_understand`（dsh-free-vision 插件） |

## 资料形态识别（先于一切分析）

盘点时先判断资料的形态，再决定各证据源的角色——同一份流水线兼容三类形态：

| 形态 | 典型文件 | 「大纲级证据」角色 | 骨架来源 | 评估载体 |
| --- | --- | --- | --- | --- |
| 教材型 | 单本/多本教材（含前言、目录、习题） | 前言/序/致读者/使用说明 | 章节目录 | 例题、章末习题 |
| 课程包型 | 讲义+课件+字幕+作业+实验 | 教学大纲/课程介绍 | 每讲/每课标题 | 作业、实验、项目 |
| 混合型 | 教材 + 补充课件 | 前言与教学大纲并读，互相印证 | 目录 + 讲次标题 | 两者并取 |
| 论文型 | 单篇/多篇论文（PDF/arXiv） | 摘要 Abstract + 引言（问题动机） | 章节标题（Intro/Related/Method/Exp/Conclusion） | 实验、消融、对比基线 |

- 论文型判定：文件名/首屏含 `Abstract`/`摘要`/`References` 等特征，或用户明说「分析这篇论文」。

- 教材型：前言/序言是**最高价值的显性证据**——作者通常在自序里写明目标读者、编写顺序的理由；全文优先通读。
- 课程包型：教学大纲/课程介绍承担同一角色；若两者都缺，逻辑链只能靠结构推断，相应结论的证据等级要降级。
- 无论哪种形态，缺了「大纲级证据」都要记入「待确认」，而不是编造。

### 论文型资料：双视角分析

论文既是被分析对象（**研究逻辑**），也是学习材料（**学习逻辑**）——两个视角都要覆盖，报告第 1–5 节回答研究逻辑，第 6 节回答学习逻辑：

**研究视角七要素**（论文为什么这样做）：
- 问题链：核心问题→子问题，痛点/缺口在哪；
- 方法动机：为什么选这个方法（基线的不足、设计选择的因果）；
- 证据链：实验设计为什么能支撑结论（消融/对比/指标选择）；
- 贡献定位：在 Related Work 中处于什么位置（增量/突破、站在谁的肩上）；
- 叙事逻辑：Abstract→Intro→…→Conclusion 为什么这样组织（漏斗式）；
- 衔接信号：每节承转（However / To address…）；
- 评估载体：实验、消融、局限性讨论。

**学习视角七要素**（我怎么学这篇论文）：
- 前置依赖：需要哪些前置知识（定理/工具/领域背景），缺的记入「待确认→建议补课」；
- 精读顺序：先读哪节、以什么顺序建立理解（Abstract→图表→Method→实验→结论）；
- 复现路径：能否复现、需要什么环境/数据、复现难点在哪；
- 延伸方向：论文打开的下游问题、可做的扩展。

## 材料预处理（落成 .md 的资料层）

技能目录 `scripts/` 自带三个脚本，把「非文本」资料先落成 .md，再走流水线：

### 图片/PDF → Markdown（pdfrender.mjs + dsocr2md.mjs，GLM-OCR）

**OCR 一律走 GLM-OCR**（智谱 bigmodel 的 `glm-ocr`，专用端点 `layout_parsing`；0.9B 高精度，文本/公式/表格识别均为 SOTA 级），输出 Markdown（`md_results` 字段：文本一字不差 + 版式还原 + 公式为 LaTeX）。中间产物与成品统一落在课程交付目录的 `3-材料/` 下：渲染 PNG → `页面渲染/`、逐页转录 .md → `逐页转录/`、直出合并稿 → `直出稿/`（逐页文件命名 `pageNNNN.png/md`，NNNN 为绝对页码）：

1. 先渲染：`node pdfrender.mjs <pdf> <页面目录> --pages=1-20 --scale=2`（MuPDF，随脚本自带；**教材/论文/书籍类内容（含文本层 PDF）一律走「渲染 + OCR」线路，不做文本层直抽**）；
2. 再转录：`node dsocr2md.mjs <页面目录> <输出目录> --delay=2000`（逐张直发 GLM-OCR；≤100 页且 ≤50MB 的 PDF 可整本直传：`node dsocr2md.mjs <file.pdf> <输出目录>`）；
3. 已存在的 .md 自动跳过，可断点续跑；Key 在 `~/.dsh/free-vision.json` 的 `zhipuApiKey` 字段（或 `ZHIPU_API_KEY` 环境变量；免费申请：https://open.bigmodel.cn）；格式限制：图片 ≤10MB、PDF ≤50MB 且 ≤100 页；
3a. 转录完成后自动跑质量对账：`node scripts/verify.mjs <逐页md目录> --total=<PDF总页数> --out=<课程目录>/3-材料/质量报告.md`（缺失页/空页/超短页/公式配对统计），异常项列入报告「待确认」；
4. 缺 Key / 额度报错 → 明确提醒用户补充，不要改用其他 OCR 模型；
5. **OCR 产出的 .md 是正式交付物之一**（主交付物是第 6 步的《课程名》逻辑链分析报告）：`combine.mjs --raw` 合并后**原样直出归档**到 `3-材料/直出稿/` 子目录（默认 `<工作目录>/课程逻辑交付/<课程名>/3-材料/直出稿/<课程名>_OCR直出.md`，用户明确指定其他目录时以用户为准；不做重排/目录处理/页码剥离，**页码与封面/CIP 页一律原样保留**），作为不可再生的原始层。
6. **参考风格优化版**（**第 5 步归档完成后自动接着执行，无需用户要求**；用户明确说「只要直出稿」时跳过本步，会话中另有指示——如"换个参考"——以用户指示为准）：以归档直出稿为输入，**参考驱动**——**默认风格样本已内置**：技能目录 `styles/数学.md`（数学风格，随预设一起分发，安装即用，无需外部文件）；优化前先 read `styles.config.json` 确认 `defaultStyle` 与 `styles` 风格集（数学/工程/文科/论文，均为相对技能目录路径），再 read 对应风格样本对照排版；用户说「用工程风格/文科风格/论文风格」→ 读 `styles` 中对应样本；**用户会话中明确指定其他风格样本时以用户指定为准**（换样本 = 换输入文件，不是改代码），持久化换默认 = 编辑 `styles.config.json` 或往 `styles/` 放新风格样本并改配置。**由模型对照风格样本的排版直接产出优化稿**；**禁止用规则脚本硬编码风格**。优化铁律：内容零改动只动排版；Obsidian 公式（行内 `$...$`、行间 fenced `$$` 独占行包裹）；无页码；封面/CIP 丢弃；目录、标题层级、术语标记加粗（`**定义 N**`/`**例 N**/`**定理**`/`**命题**`/`**证**`/`**注意**` 等，无句点）一律照风格样本逐项模仿——样本的目录形态以样本文件当时的实际写法为准（如数学风格样本现行写法：`# 目录` + `- **第X章**` 列表项加粗 + Tab 缩进 `	- X.Y 名称` 子项，条目连续无空行，无页码），风格样本改版后要重新读样本再产出，不要沿用旧版形态。优化稿默认放 `1-报告/` 子目录，文件名 `<课程名>_参考风格优化版.md`（用户明确指定时以用户为准）。篇幅大的资料用脚本化分卷流程（`scripts/stylevol/`，只负责切分/合并/校验，排版风格仍由模型对照风格样本产出）：`split.mjs` 按章切直出稿 → 分卷目录（`3-材料/风格版分卷/`，`NN-第X章-N.md`）→ 模型逐卷对照参考风格产出优化分卷 → `merge.mjs` 按序合并为成品 → `check.mjs` 校验（内容一致性+结构 QA+覆盖核对；目录区页码差异自动忽略，公式排版差异如实报告、人工判断）。全部完成后保证全稿风格统一。

### 更新模式（教材改版/补页）

同一门课资料更新时走增量流程：只转录变化的页区间（`dsocr2md.mjs --pages=起-止`）→ 重合并直出稿（`combine.mjs`）→ 只重做受影响的分卷 → 交付时靠 frontmatter 的 `source_fingerprint` 提示「资料已变，差异：…」。旧转录文件保留不删。

### 运行方式（Windows 沙箱注意）

pwsh 不能以管道捕获外部程序输出（EPERM），node 脚本必须走文件重定向：

  $node = (Get-Command node).Source
  $p = Start-Process -FilePath $node -ArgumentList '<技能目录>/scripts/dsocr2md.mjs','<页面目录>','<输出目录>' -RedirectStandardOutput "$env:TEMP\ocr.log" -RedirectStandardError "$env:TEMP\ocr.err" -Wait -PassThru -WindowStyle Hidden
  Write-Host "exit=$($p.ExitCode)"; Get-Content "$env:TEMP\ocr.log"; Get-Content "$env:TEMP\ocr.err"

ocr2md 同法，图片量大时去掉 `-Wait` 改后台运行，跑完读日志。转换产物 `<源目录>/md/` 即新的资料主目录；原始文件保留，报告的证据索引指向 md 文件与原页的对应关系。

## 深度档位

- **概览**（用户点名时）：只读大纲/目录/标题，产出课程全景 + 逻辑链主线 + 模块地图。
- **标准**（默认）：完整六步流水线，产出报告全部七节。
- **深挖**（用户点名时）：在标准之上，逐小节给出衔接证据、例题与习题的设计意图，并做多轮自洽校验。

## 流水线

### 第 0 步 任务澄清（仅必要时）

**按用户首条消息的内容直接分流**（不做「先确认无资料」的预设判断）：

1. **给了资料路径**（任意位置/任意盘符）→ 直接进入标准流水线（第 1 步资料盘点）——**资料路径优先**：同时给了路径与学习表述时走资料分支，学习表述作为分析背景；
2. **给了学习需求**（未给资料路径）→ 直接进入「自主找资料流程」（见下）。**学习需求判定是意图理解，不是形式匹配**：
   - **判据（唯一标准）**：理解用户话语**背后的意图**——是否在表达「**想获得某种知识/技能/理解/信息**」（学习行为本身）。**「想学 XX」本身就是完整的学习意图，不需要绑定任何目的**；目的（解决问题 / 达成目标 / 消除困惑）只是常见的伴随物，**不是必要条件**——纯粹兴趣、求知欲、自我提升、甚至没有理由就是想学，都算学习需求。意图成立即视为学习需求，任何表述形式都算，不限于任何句式模板（不必出现「学」字）；
   - 常见意图示例（**仅供理解「意图长什么样」，非穷举、更不是匹配模板**）：直接想学（学/掌握/入门/搞懂/了解 XX，可无目的）、为了目标而学（为了 XX 需要学什么）、能力诉求（想能 XX）、求知疑问（XX 为什么这样/原理是什么/看不懂 XX）、路径求助（怎么选教程/路线合不合理/该从哪开始/买书了怎么读）；
   - **明确不算（反例）**：给了资料并要求加工（总结/分析/改写材料 → 资料分支或普通帮助）；无学习意图的任务请求（帮我写个 XX、帮我修 bug）；
   - 拿不准时倾向视为学习需求（宁可多走一轮确认，不错过需求）；若判定为学习需求，其具体内容（含目标型的目标本身）由阶段一能力点拆解承接。
3. **两者都没给**（无路径也无学习意图，如泛泛开场/问用法）→ **告知本 agent 用法**：先 read 技能目录的 `USAGE.md`，以其内容为准完整呈现（能做什么、如何下达任务、三种输入方式、交付物、常见问题），引导用户给出资料路径或学习需求；用户给出后按 1/2 分流——仍未给则继续按 USAGE 引导，**不擅自开始任何分析、不猜测用户意图**。

其余一律不反复询问；能从文件系统发现的自己发现。材料明显残缺（缺大纲、缺一半章节）→ 记录进「待确认」，不打断流程。

### 自主找资料流程（无资料，学习需求驱动）

触发：用户没给资料路径，只给了学习需求。**迭代确认制**——以下每个阶段都以**用户明确表态**为唯一出口，未表态前绝不进入下一阶段：

**迭代原则**：以下两个阶段都采用「**主动向用户提问 + 思考 + 与用户交流讨论 + 上网搜集相关资料**」的方式反复迭代（提问用 ask_user_question，讨论用对话，搜集用 web_search）；每轮迭代都向用户汇报当前理解并请其表态。

**检索铁律（两个阶段通用）**：上网搜集时，**官网与高质量网络资源必须优先检索且不得遗漏**——官方文档 / 官网教程 / 课程官网 / 官方课程页 / 权威机构资源 / 高质量博客与教程文章，都必须在候选与汇报中呈现，不得因泛泛搜索而错过；候选清单中官网来源必须显式标注（如「官网」「官方文档」）。

1. **阶段一 · 确定能力点清单**（出口：**用户表明能力点完全确定**）
   - **本阶段的本质产出 = 需要掌握的能力点清单（多层树形结构，含前置/后置依赖）**，不是需求描述，更不是资料推荐；
   - 从能力点视角拆解：围绕用户的原始需求，反推「掌握哪些**能力点**才能覆盖它」——主动提问（主题 / 已有基础 / 用途 / 期望成果 / 深度档位），结合思考与上网搜集该领域的能力地图（课程大纲、官方技能树、行业标准、官方文档目录），逐轮给出树形清单并与用户讨论、增删、修正；
   - **能力点是多层树形结构**：既有**独立并列的一级能力点**，也有**从属的次级能力点**（子能力点），可多层嵌套——
     ```
     - 能力点
         - 能力点
             - 能力点（叶子：可学习、可检验的具体单位）
             - …
         - …
     - 能力点
         - …
     - 能力点
     ```
   - **粒度规则**：覆盖范围过大的能力点必须向下分解，直到**叶子能力点为「可学习、可检验的具体单位」**（如「会证 XX 定理」「能调优 XX 参数」「能独立实现 XX」）；父能力点是能力域/聚合，叶子是具体学习与检验单位；
   - **每个叶子能力点必须给出「掌握标准」**：即判断该能力点是否已掌握的**可检验标准**（如「能独立写出 XX 的证明」「能不看资料实现 XX 并跑通测试」「能向他人讲清 XX 的原理」），随清单一起呈现给用户确认——标准定了，「学会没有」才有客观判据；
   - **前置/后置依赖标注在叶子能力点之间**（父能力点的依赖由其子能力点推导：前置 = 全部子级前置的并集，后置 = 全部子级后置的并集）——叶子之间形成依赖关系，按拓扑序即可排出高效学习顺序（无前置依赖或前置已具备的能力点优先学）；依赖关系随树形清单一起呈现给用户确认；
   - **本阶段只确定能力点，不推荐任何资料**（资料的取舍是阶段二的事）；
   - 反复迭代直到用户明确表态「能力点确定了」，否则不进入下一阶段；
   - **留档**：表态确定后立即把树形能力点清单（叶子能力点带前置/后置/掌握标准标注）写入 `<工作目录>/课程逻辑交付/<课程名>/0-规划/能力点清单.md`（课程名 = 规范化后的需求主题；树形用 `- **能力点**` + Tab 缩进子项的 Obsidian 目录树写法，与 `styles/` 风格样本的目录形态一致），作为后续阶段与交付的依据；**同时必产能力点依赖图**：用 `mermaid2canvas.mjs` 生成 `<课程名>-能力点依赖图.canvas` 归档于 `0-规划/`（以叶子能力点为节点、依赖为边），产出后用 read 校验。
2. **阶段二 · 确定资料清单**（出口：**用户表明资料清单完全确定**）
   - **先问学习形态偏好**：用 ask_user_question 询问用户希望以哪种形态学习——① **完全书籍自学**（资料全为书籍类）② **视频课程为主** ③ **AI 自行决定** ④ 其他（用户说明）；该偏好作为资料匹配的硬约束：书籍偏好 → 候选以教材/专著/书籍类为主；视频偏好 → 候选以视频课程为主（记录课程名/讲师/平台链接）；AI 决定 → 不限制形态；其他 → 按用户说明；
   - **按已确定的能力点逐项匹配资料**：对每个能力点（标注到叶子能力点，或最近的从属层），确定需要哪些资料来覆盖（一份资料可覆盖多个能力点），并标注每条候选「覆盖的能力点」；
   - 上网检索按检索铁律执行（官网/官方文档/高质量资源必查）；
   - **候选清单固定字段（表格）**：`覆盖能力点｜名称｜来源｜链接/位置｜形态｜价值评估｜状态`——来源含官网标注；链接/位置：网络资料为 URL、本地资料为本地路径；形态为教材型·课程包型·论文型·视频型；状态为待获取·本地命中·已下载·已忽略；**价值评估必须具体**：写明该资料对其覆盖能力点的**具体价值**（如「第 3–5 章完整覆盖能力点②的证明细节，例题充足」「对能力点④提供官方 API 权威参考」「前两章讲透能力点①的前置，适合补基础」），不得只写高/中/低等笼统分级；
   - 与用户反复迭代增删改，直到用户明确表态「清单确定了」，否则不进入下一阶段；
   - **留档**：表态确定后立即把资料清单（按上述七列）写入 `<工作目录>/课程逻辑交付/<课程名>/0-规划/资料清单.md`，并在「资料落地」过程中逐项更新状态列，最终状态随交付一并保留。
3. **资料落地**（清单确定后逐项落实）
   - **本地优先**：在本地资料库（默认探测 `~/Obsidian本地库/书籍管理/资料`，探测不到则询问用户路径，以用户指定为准）按清单逐项检索；本地命中 → 直接引用原路径；
   - **网络补充**：本地没有的 → 网络检索并下载（下载根默认探测 `~/Obsidian本地库/书籍管理/下载`，以用户指定为准；PDF 存 `<下载根>/<课程名>/<原始文件名>.pdf`，网页存 `<下载根>/<课程名>/<页面名>.md` 快照）；每个下载/抓取动作执行前单独确认；
   - **缺失决断**：网络也没有的 → **让用户决断**：自行下载 or 忽略该项；**直到用户给出决断，否则停在这里**（不擅自跳过、不擅自继续）；
   - 每落实一项即更新 `0-规划/资料清单.md` 的状态列（本地命中 / 已下载 / 已忽略）；
   - 当清单资料**全部就位**（本地命中或已下载），或用户对缺失项**选择了忽略** → 进入下一步。
4. **进入标准流程**：资料形态识别 → 材料预处理（需要 OCR 则 OCR）→ 骨架提取 → 分析 → 交付（与用户上传资料完全同流程）；深度档位默认标准，用户可在任意步骤改。

### 第 1 步 资料盘点

1. 列目录、数文件、估体量、判类型；
2. 产出**资料清单表**：

   | 文件/目录 | 类型 | 覆盖范围 | 对逻辑提取的价值 |
   | --- | --- | --- | --- |

   价值判定：**高**=课程级导言（教材的前言/序/致读者/使用说明；课程的介绍/教学大纲——设计者自述目标、受众、编排顺序与意图的地方）、目录、章节导语、作业与考试说明、项目要求；**中**=讲义/课件正文、字幕；**低**=附录、参考资料、数据文件。

3. 判定课程边界：哪些资料属于这门课，哪些只是旁支。
3a. **扫描课程库（跨课程联动）**：读取 `<工作目录>/课程逻辑交付/*/1-报告/` 下已有逻辑链报告的 frontmatter（course/深度/日期/状态），建立课程清单；本课与他课的关联（先修/后继/平行）识别后写入报告第 6 节「跨课衔接」小节——跨课结论证据等级从 `[结构推断]` 起步，无法确证一律进「待确认」，不默认成立。
4. 按上方「资料形态识别」判定本次资料属于教材型/课程包型/混合型，确定大纲级证据、骨架来源与评估载体分别来自哪里。

### 第 2 步 骨架提取（先骨后肉）

1. 先读大纲、目录、标题层级，构建**模块→章节→小节**树；这一步不读正文。
2. 再按骨架读正文，每个单元记录七要素：
   - 主题；知识/技能点；
   - 引入方式（提问/例子/概念直陈/回顾旧知）；
   - 教学动作（讲/演/练/评/做）；
   - 衔接信号（回顾上节、本节目标、预告下节、承上启下句）；
   - 评估载体（例题/习题/实验/项目/考试）；
   - 篇幅与练习权重。
3. 用 grep 找信号词：目标、要求、回顾、小结、重点、难点、作业、考试、项目、实验。
4. 大型课程：按模块派发 subagent 并行提取，模板统一（每个子代理只交上面七要素的结构化结果），主代理负责综合，不直接抄子代理的推理。
5. 超大型课程（>30 模块或 >2000 页）：用 workflow 分阶段编排——阶段 1 盘点+骨架、阶段 2 按模块并行提取、阶段 3 综合+校验；中等课程沿用 subagent 并行。

### 第 3 步 顺序与依赖分析

1. 对每一对相邻环节回答「**为什么 A 在 B 前**」，从下列动因中选并写明理由：
   - 前置知识依赖（B 用到 A）；
   - 认知负荷递进（简单→复杂、具体→抽象、现象→机制）；
   - 动机铺垫（先给问题/痛点，再给方法）；
   - 工具准备（先给工具/环境，再给任务）；
   - 螺旋上升（先会用，再会原理，再会权衡）；
   - 案例驱动（先案例，再归纳理论）；
   - 项目导向（任务前置，知识按需补给）。
2. 找出**非相邻暗线依赖**（第 5 章偷偷用到第 1 章、实验课依赖理论课）。
3. 划分**阶段**（通常 3–5 个）：每阶段命名、一句话定位、入口条件、出口能力。
4. 画**模块依赖图**（mermaid flowchart；节点=环节，边=「为什么」的短语）。

### 第 4 步 设计意图推断

1. 显性证据优先：大纲的教学目标（教材形态则为前言/序）、章节导语、作业与考试权重、教师写下的「本节目的」。
2. 再由结构推断：练习密度分布、案例选择、复习点的位置、项目的时间点。
3. 识别教学策略签名：理论先行 / 案例驱动 / 螺旋上升 / 项目导向 / 习题驱动 / 混合式。
4. 每条意图标注证据等级：
   - `[资料明说]`：资料里写了；
   - `[结构推断]`：从顺序、权重、练习分布推出；
   - `[推测]`：仅从内容性质猜的，必须进「待确认」候补。

### 第 5 步 自洽性校验

- 逻辑链必须能解释**全部主要资料**；解释不了的进「待确认」。
- 闭环检查：每个环节有来处（依赖什么）与去处（支撑什么）；第一环的入口与最后一环的出口各自成立。
- 资料内部矛盾（两个文件说法冲突）如实指出，不掩盖。
- 用反事实检验：**如果去掉 X 环节会怎样？** 答不上来的环节，其存在理由可能还没找对。

### 第 6 步 交付

**指纹对比**：开始交付前，若本课已存在旧报告，先读其 frontmatter 的 `source_fingerprint`：资料指纹未变 → 提示「与上次一致」，直接沿用上次结论交付（或建议用户改深度档再挖）；指纹变化 → 列出差异来源，只对变化部分重新分析。

交付物按三类分目录归档在 `<工作目录>/课程逻辑交付/<课程名>/` 下——**同一 agent 处理多门课时每门课独立一个文件夹，互不混淆；用户明确指定其他位置时以用户为准**。**课程名规范**：课程名默认取资料目录名（或用户指令中的课程名），去除 `<>:"/\\|?*` 等非法字符与首尾空白；同一门课重复处理时保持同名，避免散成多个文件夹。

**论文形态的交付适配**：课程名 = 论文名（去扩展名）；报告七节按双视角写作（第 1–5 节研究逻辑、第 6 节学习逻辑——精读顺序/复现路径/延伸方向，替代课程版的阶段学习路径）；学习路线图 → `<论文名>-精读路线.md`；canvas → `<论文名>-方法流程.canvas`（方法-证据地图）；优化稿默认仍为数学风格，用户可说「用论文风格」（`styles/论文.md`）。

```
<课程名>/
├── 0-规划/    （自主找资料模式专属，随交付保留）能力点清单.md（树形，叶子带前置/后置/掌握标准）· 能力点依赖图.canvas（必有）· 资料清单.md（覆盖能力点｜名称｜来源｜链接/位置｜形态｜价值评估｜状态）
├── 1-报告/    <课程名>-逻辑链分析.md（必有）、<课程名>-学习路线图.md（默认）、<课程名>_参考风格优化版.md（优化稿）
│   └── 画布/  <课程名>-模块地图.canvas、<课程名>-学习路线图.canvas 等全部流程图画布（必有）
├── 2-证据/    分块七要素/证据提取文件（大课程子代理并行产物，有则归档于此）
└── 3-材料/    页面渲染/ · 逐页转录/ · 直出稿/ · 风格版分卷/ · 质量报告.md（仅资料经 OCR/转换时存在）
```

1. **主交付物**：`<课程名>-逻辑链分析.md`（七节设计逻辑报告，**默认写入 `1-报告/`**）；对话中给出要点摘要（结构 + 主线 + 关键因果句）。
1a. **学习路线图**（默认产出，用户说「不要路线图」可跳过）：`<课程名>-学习路线图.md`——沿逻辑链的 3–5 阶段学习路径、每阶段验收标准、跳步警告与加速时机，**默认写入 `1-报告/`**。
1b. **流程图 canvas 集**（必有）：报告**每出现一个 mermaid 流程图，就同步产出对应 `.canvas` 文件**——`<课程名>-模块地图.canvas`（第 3 节模块地图）、`<课程名>-学习路线图.canvas`（路线图全局路线）、`<论文名>-方法流程.canvas`（论文方法-证据地图）等，命名统一 `<课程名>-<图名>.canvas`，**全部集中写入 `1-报告/画布/` 子目录**；mermaid 保留在报告中（导出友好），图标题旁标注「Canvas 版：`画布/<文件名>.canvas`」。生成方式：用自带脚本 `scripts/mermaid2canvas.mjs <md报告> <输出.canvas> [--index=N]` 自动提取并转换（支持单行定义/带文本边/纯边三种 mermaid 行格式；报告含多个 mermaid 块时用 `--index=N` 对每个图分别转换；无 mermaid 块或解析异常会明确报错），产出后用 read 校验 JSON 合法。

3. 报告骨架（frontmatter 必填；`source_fingerprint` 为资料文件哈希摘要前 8 位，未记录可省略；尾部自检清单交付前逐项勾选，保留在报告中）：

## 铁律

1. **忠于资料**：结论都能指回具体文件与章节；不脑补、不贴通用教学论标签充数。
2. **事实与推断分家**：三个证据等级处处标注。
3. **回答「为什么这样设计」**，不写「讲了什么」。
4. **自洽优先**：宁可标「待确认」，不编衔接、不掩盖矛盾。
5. 中文交付；命令/代码/路径/文件名一律反引号包裹。
6. 长任务用 goal 工具跟踪；大课程用 subagent/workflow 分模块并行，主代理综合；预处理只新增 `md/` 产物，不改动原始资料文件；**公式一律用 Obsidian 可解析的 `$...$` / `$$...$$`（模型输出的 `\(...\)` / `\[...\]` 必须转换）；直出稿原样保留页码与封面页，参考风格优化稿不加页码、不加页间分隔，追求所见即所得**。
7. **确认制（自主找资料）**：按用户首条消息直接分流——给资料走标准流程、给需求走自主流程、都没给先告知本 agent 用法（呈现 USAGE.md）引导、不擅自开始分析；阶段一确定**能力点清单**（每条标注前置/后置依赖）、阶段二确定**资料清单**，均以用户明确表态「完全确定」为唯一出口，未表态不进入下一阶段；阶段一只定能力点、不推荐资料；上网检索官网/官方文档/高质量资源必查不遗漏；网络缺失资料由用户决断（自行下载/忽略）后才继续；**能力点清单与资料清单确定后必须留档至 `0-规划/`**；任何未经用户确认的下载/抓取/跳过动作不得执行。
