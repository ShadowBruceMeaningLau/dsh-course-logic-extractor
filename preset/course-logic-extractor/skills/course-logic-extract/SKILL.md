# 课程逻辑提取（course-logic-extract）

## 使命

给定一门课程的任意形态资料（目录、大纲、讲义、课件、字幕、习题、实验、项目说明、参考书目……），还原这门课的**设计逻辑**：

- **顺序**：课程先干什么、后干什么，为什么是这个顺序而不是别的顺序；
- **意图**：每个环节为什么存在、为什么放在这个位置、它服务于什么能力；
- **逻辑链**：把上述判断串成一条自洽、可解释、可验证的因果链。

最终交付物是**设计逻辑分析报告**，服务对象是「还没开始正式学习、想先看清全局」的人。

## 边界（什么不是本技能）

- 不是内容笔记/摘要：不逐章复述知识点，内容细节只在支撑设计判断时出现。
- 不是大纲提取：不产出设问式学习清单；本技能回答「为什么这样组织」，不回答「每章要学什么」。
- 不是课程评价：可以指出设计的得失，但服务于解释设计逻辑，不写成评测报告。

## 用户使用说明（先答再干）

用户询问「怎么用 / 如何使用 / 使用说明 / 这个 agent 怎么用 / 你能做什么」等（任何类似措辞，包括创建会话、任务写法、交付物、常见问题的提问）时：**先 read 本技能目录的 `USAGE.md`，以其内容为准完整呈现**（可直接转述全文，或按用户的具体问题聚焦相应小节），不要凭记忆自行发挥、不要省略「交付物 / 常见问题」中的关键条目。用户明确表示已了解、并给出课程资料后，再进入正常提取流程。

## 输入形态与处理

| 形态 | 处理 |
| --- | --- |
| 本地目录（最常见） | glob/pwsh 盘点 → read 逐文件读取 |
| 粘贴的文本 | 直接作为资料处理，仍先划骨架再分析 |
| HTML 课件页（导出的网页课程） | 直接读源码提取标题与正文（标题=骨架，正文=内容）；页面文字已包含在文件里，无需 OCR，图片多为配图 |
| 网页课程/URL | 能访问则抓取目录与章节页，不能则请用户提供文本 |
| 图片/扫描件/无文本层 PDF | 用自带脚本 `scripts/dsocr2md.mjs`（**DeepSeek-OCR，硅基流动免费托管**——「DeepSeek 网页识图」路线的程序化版本）批量转 Markdown；单张「看图理解」用 `image_understand`（dsh-free-vision 插件） |

## 资料形态识别（先于一切分析）

盘点时先判断资料的形态，再决定各证据源的角色——同一份流水线兼容三类形态：

| 形态 | 典型文件 | 「大纲级证据」角色 | 骨架来源 | 评估载体 |
| --- | --- | --- | --- | --- |
| 教材型 | 单本/多本教材（含前言、目录、习题） | 前言/序/致读者/使用说明 | 章节目录 | 例题、章末习题 |
| 课程包型 | 讲义+课件+字幕+作业+实验 | 教学大纲/课程介绍 | 每讲/每课标题 | 作业、实验、项目 |
| 混合型 | 教材 + 补充课件 | 前言与教学大纲并读，互相印证 | 目录 + 讲次标题 | 两者并取 |

- 教材型：前言/序言是**最高价值的显性证据**——作者通常在自序里写明目标读者、编写顺序的理由；全文优先通读。
- 课程包型：教学大纲/课程介绍承担同一角色；若两者都缺，逻辑链只能靠结构推断，相应结论的证据等级要降级。
- 无论哪种形态，缺了「大纲级证据」都要记入「待确认」，而不是编造。

## 材料预处理（落成 .md 的资料层）

技能目录 `scripts/` 自带三个脚本，把「非文本」资料先落成 .md，再走流水线：

### 图片/PDF → Markdown（pdfrender.mjs + dsocr2md.mjs，DeepSeek-OCR）

**OCR 一律走 DeepSeek-OCR**（硅基流动 SiliconFlow 免费托管的 `deepseek-ai/DeepSeek-OCR`，即「DeepSeek 网页识图」同源能力的 API 路线），输出 Markdown（文本一字不差 + 版式还原 + 公式为 LaTeX）：

1. 先渲染：`node pdfrender.mjs <pdf> <页面目录> --pages=1-20 --scale=2`（MuPDF，随脚本自带；**教材/论文/书籍类内容（含文本层 PDF）一律走「渲染 + OCR」线路，不做文本层直抽**）；
2. 再转录：`node dsocr2md.mjs <页面目录> <输出目录> --delay=2000`（逐张直发 DeepSeek-OCR）；
3. 已存在的 .md 自动跳过，可断点续跑；Key 在 `~/.dsh/free-vision.json`（或 `SILICONFLOW_API_KEY`，免费申请：https://cloud.siliconflow.cn）；
4. 缺 Key / 额度报错 → 明确提醒用户补充，不要改用其他 OCR 模型；
5. **OCR 产出的 .md 是正式交付物之一**（主交付物是第 6 步的《课程名》逻辑链分析报告）：`combine.mjs --raw` 合并后**原样直出归档**到课程交付文件夹的 `材料层/` 子目录（默认 `<工作目录>/课程逻辑交付/<课程名>/材料层/`，用户明确指定其他目录时以用户为准；不做重排/目录处理/页码剥离），作为不可再生的原始层。「所见即所得」铁律：md 无翻页概念，**页码完全去掉**，无页间分隔、连续内容不断行；封面/CIP/版权页元数据丢弃。
6. **参考风格优化版**（用户要求时，如"换个参考"）：以归档直出稿为输入，**参考驱动**——**默认参考已内置**：技能目录 `reference/高等代数.md`（随预设一起分发，安装即用，无需外部文件）；优化前先 read `reference.config.json` 确认 `defaultReference`（相对路径相对技能目录解析），再 read 该参考文件对照风格；**用户会话中明确指定其他参考时以用户指定为准**（换参考 = 换输入文件，不是改代码），持久化换默认 = 编辑 `reference.config.json` 或往 `reference/` 放新笔记并改配置。**由模型对照参考笔记的排版风格直接产出优化稿**；**禁止用规则脚本硬编码风格**。优化铁律：内容零改动只动排版；Obsidian 公式（行内 `$...$`、行间 fenced `$$` 独占行包裹）；无页码；封面/CIP 丢弃；目录、标题层级、术语标记加粗（`**定义 N**`/`**例 N**/`**定理**`/`**命题**`/`**证**`/`**注意**` 等，无句点）一律照参考笔记逐项模仿——参考的目录形态以参考文件当时的实际写法为准（如《高等代数》现行写法：`# 目录` + `- **第X章**` 列表项加粗 + Tab 缩进 `	- X.Y 名称` 子项，条目连续无空行，无页码），参考笔记改版后要重新读参考再产出，不要沿用旧版形态。

### 运行方式（Windows 沙箱注意）

pwsh 不能以管道捕获外部程序输出（EPERM），node 脚本必须走文件重定向：

  $node = (Get-Command node).Source
  $p = Start-Process -FilePath $node -ArgumentList '<技能目录>/scripts/dsocr2md.mjs','<页面目录>','<输出目录>' -RedirectStandardOutput "$env:TEMP\ocr.log" -RedirectStandardError "$env:TEMP\ocr.err" -Wait -PassThru -WindowStyle Hidden
  Write-Host "exit=$($p.ExitCode)"; Get-Content "$env:TEMP\ocr.log"; Get-Content "$env:TEMP\ocr.err"

ocr2md 同法，图片量大时去掉 `-Wait` 改后台运行，跑完读日志。转换产物 `<源目录>/md/` 即新的资料主目录；原始文件保留，报告的证据索引指向 md 文件与原页的对应关系。

## 深度档位

- **概览**（用户点名时）：只读大纲/目录/标题，产出课程全景 + 逻辑链主线 + 模块地图。
- **标准**（默认）：完整六步流水线，产出报告全部七节。
- **深挖**（用户点名时）：在标准之上，逐小节给出衔接证据、例题与习题的设计意图，并做多轮自洽校验。

## 流水线

### 第 0 步 任务澄清（仅必要时）

- 没有资料路径 → 用 ask_user_question 问一次：资料路径 + 深度档位。
- 其余一律不反复询问；能从文件系统发现的自己发现。
- 材料明显残缺（缺大纲、缺一半章节）→ 记录进「待确认」，不打断流程。

### 第 1 步 资料盘点

1. 列目录、数文件、估体量、判类型；
2. 产出**资料清单表**：

   | 文件/目录 | 类型 | 覆盖范围 | 对逻辑提取的价值 |
   | --- | --- | --- | --- |

   价值判定：**高**=课程级导言（教材的前言/序/致读者/使用说明；课程的介绍/教学大纲——设计者自述目标、受众、编排顺序与意图的地方）、目录、章节导语、作业与考试说明、项目要求；**中**=讲义/课件正文、字幕；**低**=附录、参考资料、数据文件。

3. 判定课程边界：哪些资料属于这门课，哪些只是旁支。
4. 按上方「资料形态识别」判定本次资料属于教材型/课程包型/混合型，确定大纲级证据、骨架来源与评估载体分别来自哪里。

### 第 2 步 骨架提取（先骨后肉）

1. 先读大纲、目录、标题层级，构建**模块→章节→小节**树；这一步不读正文。
2. 再按骨架读正文，每个单元记录七要素：
   - 主题；知识/技能点；
   - 引入方式（提问/例子/概念直陈/回顾旧知）；
   - 教学动作（讲/演/练/评/做）；
   - 衔接信号（回顾上节、本节目标、预告下节、承上启下句）；
   - 评估载体（例题/习题/实验/项目/考试）；
   - 篇幅与练习权重。
3. 用 grep 找信号词：目标、要求、回顾、小结、重点、难点、作业、考试、项目、实验。
4. 大型课程：按模块派发 subagent 并行提取，模板统一（每个子代理只交上面七要素的结构化结果），主代理负责综合，不直接抄子代理的推理。

### 第 3 步 顺序与依赖分析

1. 对每一对相邻环节回答「**为什么 A 在 B 前**」，从下列动因中选并写明理由：
   - 前置知识依赖（B 用到 A）；
   - 认知负荷递进（简单→复杂、具体→抽象、现象→机制）；
   - 动机铺垫（先给问题/痛点，再给方法）；
   - 工具准备（先给工具/环境，再给任务）；
   - 螺旋上升（先会用，再会原理，再会权衡）；
   - 案例驱动（先案例，再归纳理论）；
   - 项目导向（任务前置，知识按需补给）。
2. 找出**非相邻暗线依赖**（第 5 章偷偷用到第 1 章、实验课依赖理论课）。
3. 划分**阶段**（通常 3–5 个）：每阶段命名、一句话定位、入口条件、出口能力。
4. 画**模块依赖图**（mermaid flowchart；节点=环节，边=「为什么」的短语）。

### 第 4 步 设计意图推断

1. 显性证据优先：大纲的教学目标（教材形态则为前言/序）、章节导语、作业与考试权重、教师写下的「本节目的」。
2. 再由结构推断：练习密度分布、案例选择、复习点的位置、项目的时间点。
3. 识别教学策略签名：理论先行 / 案例驱动 / 螺旋上升 / 项目导向 / 习题驱动 / 混合式。
4. 每条意图标注证据等级：
   - `[资料明说]`：资料里写了；
   - `[结构推断]`：从顺序、权重、练习分布推出；
   - `[推测]`：仅从内容性质猜的，必须进「待确认」候补。

### 第 5 步 自洽性校验

- 逻辑链必须能解释**全部主要资料**；解释不了的进「待确认」。
- 闭环检查：每个环节有来处（依赖什么）与去处（支撑什么）；第一环的入口与最后一环的出口各自成立。
- 资料内部矛盾（两个文件说法冲突）如实指出，不掩盖。
- 用反事实检验：**如果去掉 X 环节会怎样？** 答不上来的环节，其存在理由可能还没找对。

### 第 6 步 交付

交付物至多两类——**主交付物必有；材料交付物仅当资料经过 OCR/转换时才存在**：

1. **主交付物**：`<课程名>-逻辑链分析.md`（七节设计逻辑报告，**默认写入 `<工作目录>/课程逻辑交付/<课程名>/`**——同一 agent 处理多门课时每门课独立一个文件夹，互不混淆；用户明确指定其他位置时以用户为准）；对话中给出要点摘要（结构 + 主线 + 关键因果句）。
2. **材料交付物**（有条件）：预处理阶段 OCR/转换产出的 `.md`（**默认归档到同课程的 `材料层/` 子目录**；用户明确指定时以用户为准）——它既作为分析用的资料层，也随报告一并交付。**若资料本就是可直接读取的形态（`.py`/`.js` 等代码文件、`.txt`、已有 `.md`、HTML 源码等），不发生任何转换，则无材料交付物**——原始文件本身就是资料层，报告的证据索引直接指向原始文件（文件路径·行号/模块/函数），不得为凑交付物而伪造转换产物。
3. 报告骨架：

   ```
   # 《课程名》逻辑链分析
   1. 课程全景：一句话定位 / 目标受众 / 学完能做什么 / 阶段划分总览
   2. 逻辑链主线：一段话讲完「先什么、后什么、为什么」，再分阶段展开，每步因果句
   3. 模块地图与依赖：mermaid 图 + 文字解释 + 暗线依赖
   4. 逐环节设计意图：每环节「定位 / 为什么在这里 / 与前后衔接 / 证据与等级」
   5. 教学策略识别：签名 + 依据
   6. 学习路线建议：沿逻辑链的学法 / 每阶段验收标准 / 跳步警告 / 何时可加速
   7. 待确认清单
   附录 A：资料清单   附录 B：证据索引（结论 ← 出处文件·章节）
   ```

## 铁律

1. **忠于资料**：结论都能指回具体文件与章节；不脑补、不贴通用教学论标签充数。
2. **事实与推断分家**：三个证据等级处处标注。
3. **回答「为什么这样设计」**，不写「讲了什么」。
4. **自洽优先**：宁可标「待确认」，不编衔接、不掩盖矛盾。
5. 中文交付；命令/代码/路径/文件名一律反引号包裹。
6. 长任务用 goal 工具跟踪；大课程用 subagent/workflow 分模块并行，主代理综合；预处理只新增 `md/` 产物，不改动原始资料文件；**公式一律用 Obsidian 可解析的 `$...$` / `$$...$$`（模型输出的 `\(...\)` / `\[...\]` 必须转换）；合并成品不加页码、不加页间分隔，追求所见即所得**。
